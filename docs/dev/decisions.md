# 決策紀錄

**收錄標準**：看到專案現在的樣子，未來的自己或 Agent 會不會問「為什麼是這樣？」會的話就記一行。
這台電腦的環境設定寫在 `CLAUDE.md`，工作方式和偏好寫在 `workflow.md`，不放這裡。

只新增，不修改舊的紀錄；決定改變時，新增一行說明新的決定。

| 日期 | 決定 | 原因 | 考慮過的其他選項 |
|---|---|---|---|

| 2026-10-04 | OpenAI 的轉錄選項用 `whisper-1` | OpenAI 的模型中，只有它提供逐字時間戳 | `gpt-transcribe`、`gpt-4o-transcribe-diarize` |
| 2026-10-04 | A/B test 時，兩種轉錄服務用不同的 `--edit-dir` | 逐字稿有快取，同一個資料夾會讓第二次直接讀到第一次的結果 | 在逐字稿檔名加上服務名稱 |

| 2026-10-04 | 中文字幕測試另開新檔 `test_render_captions_zh.py` | 不改官方的測試檔，合併官方更新時比較不會衝突 | 加在 `test_render_captions.py` 裡 |
| 2026-10-04 | 簡繁轉換（OpenCC）延後，等真影片實測後再決定 | Scribe 可能直接輸出繁體，先不增加套件依賴 | 一開始就加入 OpenCC |
| 2026-10-06 | 中文字幕和 `takes_packed.md` 用 OpenCC `s2twp` 轉成台灣繁體（取代 2026-10-04「OpenCC 延後」） | 實測 Scribe 輸出的是簡體；`s2twp` 連用語一起轉（视频 → 影片） | 不轉換，請使用者自己改；`s2t`（只轉字形，不轉用語） |

| 2026-10-06 | `pack_transcripts.py` 自動判斷中文，不加參數 | 和 `render.py` 共用 `looks_chinese()`；英文輸出完全不變 | 加 `--lang` 參數 |
| 2026-10-08 | 剪輯專案檔的匯出格式用 Final Cut Pro 7 XML（新增 `export_xml.py`） | DaVinci、Premiere 都能讀；能表達多軌（片段、問題卡、聲音）和素材總長度，剪輯師才能把剪掉的部分拉回來 | CMX3600 EDL（只有單軌剪輯點）、新版 FCPXML（Premiere 不能讀）、OpenTimelineIO（要多裝套件） |
| 2026-10-08 | 問題卡在 XML 裡改用同名的 PNG，不用算繪時的 `.mov` | DaVinci 免費版不一定能解 qtrle 編碼的 `.mov`；PNG 一定能讀，在時間軸上也能直接調整長度 | 直接引用 `.mov` |
| 2026-10-08 | SKILL.md 的 Helpers 清單加入 `export_xml.py`，和官方版產生差異 | SKILL.md 是 AI 讀的說明，不寫的話 AI 不知道有這個工具可以用 | 只寫在 README，不改 SKILL.md |
| 2026-10-09 | XML 的 `<file>` 一律寫起始時間碼 `00:00:00:00` | 沒寫的話，DaVinci 匯入後聲音片段會離線（用 4 份只改一處的測試檔確認，見 `specs/2026-10-08-xml-export.md` 修訂紀錄） | 讀素材本身的時間碼（ffprobe 的 `timecode` 標籤）：沒有這類素材可以驗證，留到之後 |
| 2026-10-09 | 字幕不放進 XML，另外匯入 `master.srt` | SRT 每套剪輯軟體都讀得懂；FCP 7 XML 的字幕寫法各家不一。代價是字幕和片段沒有連結，剪輯師改了片段要手動改字幕 | 把字幕寫進 XML |
| 2026-10-09 | 中文字幕每句上限依輸出畫面寬度計算（直式約 10 字、橫式維持 14 字）；畫面在 render.py 之後才裁切時，用 `--sub-max-chars` 指定 | 直式實測一行只放得下約 10 字，14 字會被播放器自動折行並切斷詞。render.py 量不到之後才裁切的畫面，所以需要參數讓 AI 指定 | 固定改成 10 字（橫式字幕會變太碎）；只加參數不自動計算（AI 容易忘記） |
| 2026-10-09 | 中文字幕超過上限時，切點優先選標點 → 停頓 → 最後一個詞邊界；數字和單位不拆、標點不放句首；太短的句子從前一句挪字，兩半長度盡量平均 | 只把上限改小會切出「我 95 / 分可不可以」「…看 / 一下」；挪最少字會讓後半句從「的」開頭 | 只改上限；讓 Claude 依意思斷句（效果最好，但要改流程、花 token，列入下一步） |
| 2026-10-09 | 中文字幕說話者換人一定斷句，`。？！` 一定斷句；不到 0.8 秒的句子併入前後句；字幕不重疊 | 主持人的「嗯」會黏在醫師句子裡；「存在的。好，」把下一句的開頭帶進來；長度 0 的字補成 0.4 秒會和下一句同時出現 | 只靠停頓和標點斷句（原本的做法） |
| 2026-10-09 | 中文字幕句中的停頓標點換成 En space（U+2002） | 全形空格太開、一般空格太窄（比較圖 `podcast_test/edit/vertical/verify/separator_compare.png`）；兩個半形空格可能被播放器合併成一個 | 全形空格 U+3000；兩個半形空格；保留標點 |
| 2026-10-09 | 中文字幕顯示不到 0.2 秒、又無法合併的句子直接拿掉 | 主持人的「嗯」夾在兩句之間只剩 0.06 秒，只會閃一下；這類字多半是附和或口頭的「對」 | 保留（畫面會閃）；從下一句挪字過來（程式較複雜，之後需要再做） |
| 2026-10-09 | 判斷中文時只排除日文（標記 `ja`／`jpn`，或文字有假名），其他語言標記仍會再看漢字比例 | 漢字多的日文會被當成中文、轉成繁體字形；但 Scribe 可能把中英夾雜的中文標成 `eng`，漢字比例能救回來 | 有語言標記就完全相信它（較簡單，但失去上述保護） |

| 2026-10-09 | 字幕字型依作業系統給預設值，`--sub-font` 可覆蓋 | 符合「skill 修改必須通用」：Yu Gothic 只有 Windows 有 | 寫死 Yu Gothic（和中文的 Microsoft JhengHei 一樣只適用 Windows） |
