# 字幕高度依畫面比例決定
日期：2026-10-09　狀態：已同意

來自 `工作地圖.md`「修正」清單的「字幕高度寫死」，也是「日文雙語字幕」第 2 階段的前置條件。

## 給我看的（白話，10 行以內）
- 要做什麼：字幕離畫面底部的高度依畫面比例自動決定：直式維持現在的高度（避開短影音 App 的按鈕），橫式放低到接近底部；另外加 `--sub-margin` 讓使用者自己指定
- 為什麼：現在寫死在畫面高度約 30% 的位置，是為直式短影音設計的；橫式影片字幕落在人物胸口（podcast 10/8、日文 B 段都遇到）。10/8 是用「先不燒字幕、再另外用 ffmpeg 燒」繞過
- 怎麼做：算繪時量畫面的寬高。直式（高 > 寬）維持現在的值；橫式和方形改成離底部約 8%。`--sub-margin 百分比` 可以覆蓋（例：`--sub-margin 5`）
- 不做什麼：字級、字型、顏色不動；不做「依鏡頭內容避開人臉」
- 怎樣算完成：橫式的 B 段和 podcast 字幕在畫面下方；直式版本（podcast `vertical`）位置和現在一樣；原有測試全過

## 給 Agent 的（細節）
- 資料流：`render.py` 算繪 `base` → 量 `base` 的寬高（`probe_dimensions`，`zh_max_width` 已在用）→ 決定 `MarginV` → `build_final_composite()` 的 `force_style` → 燒進畫面。`--build-subtitles` 產生的 `master.srt` 和 EDL `subtitles` 指定的檔案都走這條路。畫面在 render.py 之後才裁切時（例：16:9 算繪後依鏡頭裁成 9:16），量到的是裁切前的比例，要由 AI 傳 `--sub-margin`（同 `--sub-max-chars` 的情況）
- 會影響的檔案：`helpers/render.py`（`sub_force_style()`、`main()`、`--sub-margin`）、`SKILL.md`（字幕樣式段落、Helpers 清單）、測試（新檔 `tests/test_render_sub_margin.py`）
- 不能改動的地方：直式（高 > 寬）的 `MarginV=90` 不變；所有語言的字級、字型、描邊不變；量不到寬高時維持 90（和現在一樣）。（怎麼確認：用 main 的程式和新程式對 podcast `vertical`、podcast 16:9、B 段各算一次 `force_style` 並比對；輸出寫到暫存資料夾）
- 通用性檢查：依畫面比例自動判斷，任何語言、任何素材都適用；`--sub-margin` 讓使用者依自己的平台調整；不寫死某個人的偏好值
- 技術細節：
  - libass 把 SRT 的座標換算到 `PlayResY=288`，所以 `MarginV = 288 × 百分比 / 100`。直式 90 ≈ 31%；橫式預設 8% ≈ 23
  - 橫式 8% 的理由：一般影片的字幕安全範圍是離邊緣 5～10%；podcast 10/8 用過 `MarginV=12`（約 4%），使用者接受，但太貼近底部，播放器的控制列出現時可能被擋住。實作後用 B 段截圖確認，必要時在修訂紀錄調整
  - `--sub-margin` 收 0～50 的百分比，超出範圍直接報錯
  - 和官方版的差異：官方註解寫「MarginV 不是品味而是安全區規則，不要低於 75」，指的是直式短影音；橫式沒有 App 按鈕的問題，所以只在橫式放低。官方 SKILL.md 寫 `bold-overlay` 是 `MarginV=35`，但程式是 90（官方 87f00c6 改程式時沒改文件），這次一併把 SKILL.md 改成實際行為
