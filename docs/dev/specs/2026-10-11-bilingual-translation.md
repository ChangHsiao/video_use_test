# 翻譯與雙語字幕
日期：2026-10-11　狀態：已完成

屬於「日文雙語字幕」第 2 階段，全部階段見專案根目錄的 `工作地圖.md`。實測素材和試譯結果見 `ja_test/edit/project.md`（Session 1）。

## 給我看的（白話，10 行以內）
- 要做什麼：日文影片燒上雙語字幕，中文在上、日文在下（日文字小一點），兩行都用說話者的顏色；AI 翻譯時套用詞彙表，並交出一份審稿清單
- 為什麼：10/10 試譯照日文字幕一句翻一句，出現「去」「所以」「有」單獨一句；日文常省略主詞、受詞，照字面翻看不懂（例：「瑪修會很不得了」其實是說瑪修那段劇情會很催淚）
- 怎麼做：① 先用現有的規則產生日文字幕草稿（每句都已經有時間和顏色）② AI 把草稿裡連續的幾句照意思合併成完整的一句，同時修正聽錯的詞（秋生 → 終章）並翻成中文，把省略的意思補回來，拿不準的地方標記起來 ③ 新的小工具把 AI 的結果組成雙語字幕檔，順便檢查有沒有漏句、字數有沒有超過，再產生審稿清單 ④ 用現有的 render.py 燒進影片
- 不做什麼：梗的加註（列入待辦）、兩人同時說話、直式、匯入 DaVinci、詞彙表的固定格式
- 怎樣算完成：B 段（2 分 36 秒）雙語預覽燒好；中文不再出現單獨的連接詞或只有一個字的句子；詞彙表的譯名都套用；審稿清單列出所有猜測和改過的日文；新工具的測試和原有測試全部通過

**新名詞**：「草稿的句子編號」＝ render.py 產生的 `master.srt` 每一句前面的號碼。AI 不用自己寫時間，只要說「第 41～43 句合成一句」，工具就會拿第 41 句的開始時間、第 43 句的結束時間。懂到「AI 只負責文字，時間交給程式」這個程度就夠了。

## 給 Agent 的（細節）
- 資料流：剪輯確定 → `render.py --subtitles-only --sub-lang ja` → `master.srt`（日文草稿：規則斷句、說話者顏色、修正過的說話者）→ Claude 讀草稿 + 詞彙表 + `takes_packed.md`，寫 `translation.json` → 新工具 `helpers/bilingual_srt.py` → `master_bilingual.srt` + 單語言的 `master_ja.srt`、`master_zh-tw.srt` + `translation_review.md` → 使用者看審稿清單，改 `translation.json` 後重跑工具 → EDL `subtitles: master_bilingual.srt`，`render.py --preview --sub-lang zh-tw`（不加 `--build-subtitles`）→ 成品
  - 草稿重新產生（剪輯改了）時句子編號會變：工具第一次執行時在 `translation.json` 寫入草稿的 SHA-256，之後草稿內容不同就報錯，不默默錯位
- 會影響的檔案：新增 `helpers/bilingual_srt.py`、`tests/test_bilingual_srt.py`；修改 `SKILL.md`（Helpers 清單、Subtitles 段落加「翻譯與雙語」）；`render.py` 只在 `zh_max_width()` 加選填參數 `cap`（2026-10-11 修訂，見修訂紀錄）
- 不能改動的地方：`render.py` 的 `en`／`zh-tw`／`ja` 字幕輸出完全不變（`cap` 預設值等於原本的上限；比對新舊 `zh_max_width` 在各種畫面尺寸的結果，加上既有測試確認）（2026-10-11 修訂，見修訂紀錄）；沒有 `translation.json` 的專案流程不變
- 通用性檢查：
  - 語言對不寫死：`source_lang`、`target_lang` 都取自 `render.SUB_LANGS`（`en`、`zh-tw`、`ja`），例如英文影片配中文字幕也能用
  - 字型沿用 render.py 各語言的預設字型（日文依作業系統），`--src-font` 可覆蓋；日文行大小 `--src-scale`（預設 0.75）
  - 詞彙表是使用者專案裡的檔案（例：`glossaries/fgo.md`），路徑記在該影片的 `project.md`；skill 不規定格式，只規定 Claude 怎麼用
  - 翻譯規則（補省略、意譯、標記猜測）寫在 SKILL.md，適用任何語言對
- 技術細節：
  - **雙語字幕格式**（2026-10-11 實驗確認，scratchpad `bitest/`）：同一個 SRT，每句兩行，`<font color="#說話者色">中文\n<font face="Yu Gothic" size="14">日文</font></font>`。燒字幕時 `force_style` 的 `FontSize=18` 是中文行，`size="14"`（18 × 0.75 取整數）只影響日文行；`MarginV` 決定的是最下面一行（日文）的位置，中文自動疊在上面
  - **`translation.json`**（Claude 寫）：
    ```json
    {
      "draft": "master.srt",
      "source_lang": "ja",
      "target_lang": "zh-tw",
      "draft_sha256": "（工具第一次執行時寫入）",
      "cues": [
        {"from": 79, "to": 82, "src": "もう私はやばいって思ってるんで バスタオルを持っていこうと思って",
         "tr": "我已經覺得自己一定會哭爆 所以打算帶條大浴巾去"},
        {"from": 35, "to": 35, "src": "マシュはヤバいですよ", "tr": "瑪修那段真的會很催淚喔",
         "check": "やばい 依後文（哭、浴巾）推測為催淚"}
      ],
      "drop": []
    }
    ```
    - `from`～`to`：草稿的句子編號（含頭尾）。所有群組依時間排列、互不重疊、彼此相接；草稿的每一句要嘛在某個群組裡，要嘛在 `drop` 裡，否則報錯並列出漏掉的編號
    - `src`：顯示的原文（Claude 可以修正聽錯的詞、去掉口吃，但不改意思）；`tr`：譯文
    - `check`（選填）：拿不準的原因，會進審稿清單
    - 一句太長時拆成兩組（例：`79–80`、`81–82`），每組各自一句完整的意思；不能在草稿的一句中間拆開（需要的話，用較小的 `--sub-max-chars` 重新產生草稿再寫）
  - **工具檢查**（`bilingual_srt.py`）：
    - 錯誤（不輸出）：編號漏掉、重複、超出範圍、順序錯；`src`／`tr` 空白；草稿 SHA-256 和記錄的不同
    - 警告（照樣輸出）：一組跨了不同說話者（顏色取第一句，提醒 Claude 改成依說話者拆開）；`tr` 超過字寬上限（預設依第一個素材的畫面寬度，`render.zh_max_width(cap=36)`：16:9 一行 18 字、9:16 約 10 字；`--max-chars` 可覆蓋）（2026-10-11 修訂，見修訂紀錄）；`src` 超過原文行在畫面上實際放得下的長度（`render.zh_max_width` 不封頂的寬度 ÷ 0.75，16:9 約 46 字）（2026-10-11 第二次修訂，見修訂紀錄）
    - 時間：開始＝第 `from` 句的開始，結束＝第 `to` 句的結束（草稿本來就不重疊，合併後也不重疊）
    - 顏色：從草稿第 `from` 句的 `<font color>` 取得；草稿沒有顏色就不加
  - **`translation_review.md`**（工具產生）：三個部分
    1. Claude 標記的句子（`check`）：編號、時間、說話者、原文、譯文、原因
    2. 原文被改過的句子：合併後的草稿文字和 `src` 去掉空白、標點後不同的，列出「草稿 → 修正」（例：秋生 → 終章），讓使用者確認聽寫修正
    3. 工具的警告
  - **SKILL.md 新增「Translation and bilingual captions」**（英文，和其他段落一致）：
    - 只在剪輯確定之後做（沿用既有規則）
    - 有詞彙表就先讀；譯名照詞彙表；詞彙表沒有的人名、專有名詞標 `check`，不自己加進詞彙表
    - 依意思合併草稿句子，一組是一個完整的意思，中文讀起來不能只剩連接詞或一個字
    - 同一個人連續說的話，只要中文放得進一行就合成一句；中文可以寫得精簡，但意思不能少；日文行比中文長是語言差異，不用遷就（2026-10-11 第二次修訂，見修訂紀錄）
    - 原文常省略主詞、受詞（日文尤其明顯）：依上下文把中文需要的補回來；只靠語氣的詞（やばい、すごい）翻出實際的意思；推測的地方標 `check`
    - 口語、保留說話者的語氣；跨說話者的句子依說話者拆開（顏色不同）
    - 產生後把 `translation_review.md` 交給使用者看，修改後重跑工具再算繪
  - 測試：群組驗證（漏號、重複、順序、drop）、時間與顏色取自草稿、雙語行格式、SHA-256 檢查、跨說話者警告、字寬警告、原文修正比對；用小型假 SRT，不需要影片
