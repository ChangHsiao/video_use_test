# 日文逐字稿不被當成中文
日期：2026-10-09　狀態：已完成

屬於「日文雙語字幕」第 0 階段，全部階段見專案根目錄的 `工作地圖.md`。

## 給我看的（白話，10 行以內）
- 要做什麼：程式判斷「這份逐字稿是不是中文」時，不再把日文誤判成中文
- 為什麼：現在只看「漢字有沒有超過一半」，漢字多的日文會被當成中文，`takes_packed.md`（給 AI 讀的逐字稿）會被轉成繁體字形（学 → 學），AI 讀到的就不是原文
- 怎麼做：兩道檢查。① Scribe 標記為日文（`ja`／`jpn`）就判斷「不是中文」；② 沒有標記時，逐字稿裡出現假名（ひらがな、カタカナ）也判斷「不是中文」
- 不做什麼：日文字幕規則、翻譯、顏色（第 1、2 階段）；不改中文和英文的判斷結果
- 怎樣算完成：日文逐字稿打包後保持原文；原有測試全部通過；新增日文的測試

## 給 Agent 的（細節）
- 資料流：Scribe 轉錄 JSON（`language_code`、`words`）→ `zh_text.looks_chinese()` → ① `pack_transcripts.py` 決定是否用中文規則（去空格 + OpenCC）產生 `takes_packed.md`，AI 依此剪輯；② `render.py` 在 `--sub-lang en` 時決定要不要警告「看起來是中文」。使用者看到的成品不直接受影響（字幕語言由 Claude 傳 `--sub-lang` 決定）
- 會影響的檔案：`helpers/zh_text.py`（`looks_chinese()`）、`tests/test_render_captions_zh.py`（`LooksChineseTests` 加測試）
- 不能改動的地方：`zh`／`zho`／`cmn`／`yue` 仍判斷為中文；沒有語言標記的中文仍靠漢字比例判斷為中文；英文結果不變；函式名稱和呼叫方式不變（`pack_transcripts.py`、`render.py` 不用改）
- 通用性檢查：任何使用者轉錄日文都受益；中文、英文、其他語言的判斷結果不變；不依賴作業系統或個人設定，沒有個人化的部分
- 技術細節：
  - Scribe 實際回傳三碼語言代碼（中文素材是 `zho`），日文預期是 `jpn`；兩碼 `ja` 一起處理
  - 只排除日文，不採用「有語言標記就完全相信它」：Scribe 若把中英夾雜的中文標成 `eng`，現在的漢字比例仍能救回來，不想失去這個保護
  - 假名範圍：平假名 U+3040–U+309F、片假名 U+30A0–U+30FF。韓文（諺文）不在漢字範圍內，本來就不會被誤判，不用處理
