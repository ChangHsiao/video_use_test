# Recipes

每份 recipe 記錄一類影片的做法，例如「把長訪談整理成直式短片」。內容是做過這類影片之後整理出來的流程和教訓，讓下一次做同類影片的 AI 不用從頭摸索。

AI 在提出剪輯策略之前，如果素材符合某份 recipe，要先讀它（`SKILL.md` 的 Recipes 段落有寫這條規則）。

## recipe 不是固定風格

video-use 的原則是不提供預設風格（No presets），每支影片的風格都要和使用者討論後決定。recipe 也遵守這個原則：它記錄的是「流程怎麼走」和「哪裡容易出錯」，風格上的選擇只能當作建議，要問過使用者才能用。

## 內容分三種

寫 recipe 時，每一條內容都要先判斷屬於哪一種，再放進對應的段落。

**1. 通用做法**：換一支影片、換一種語言、換一台電腦都成立的做法。AI 直接照做。

> 例：配音每一段各自生成一個音檔。這樣某一段念錯時，只要重做那一段。

**2. 預設**：合理的起點，但使用者可能有不同想法。AI 要先提出來問使用者，同意了才用。每條都要寫理由，讓使用者知道為什麼建議這樣做。

> 例：講者說話時，臉上不放任何圖片或文字。理由是觀眾這時候在看他說話。

**3. 範例**：某一支影片實際做了什麼。只給 AI 參考，不能直接套到新影片上。

> 例：那支影片用了某個台灣腔的 AI 聲音，旁白加速到 1.15 倍。

## 每份 recipe 的段落

| 段落 | 要寫什麼 | 為什麼要有 |
|---|---|---|
| 開頭 | 一句話說明這類影片是什麼 | 讓讀的人馬上知道這份 recipe 在講哪一類影片 |
| 適合／不適合 | 什麼樣的素材適合用這個做法，什麼樣的不適合 | AI 一開始就能判斷要不要用這份 recipe |
| 流程 | 從拿到素材到輸出成品的步驟（通用做法） | 這是 recipe 的主體 |
| 預設 | 建議的選擇和理由（要先問使用者） | 給使用者一個起點，不用每件事都從零討論 |
| 踩過的坑 | 做的時候出過的錯，以及怎麼避免（通用做法） | 避免下一次再犯同樣的錯 |
| 加快算繪 | 讓輸出影片那一步變快的方法；沒有就不寫這段 | 有些做法要算很久，知道怎麼加快可以省很多時間 |
| 還沒解決 | 發現了、但還沒修好的問題 | 讓下一個人知道哪裡還有問題，不要以為現在的做法沒問題 |
| 範例 | 實際做過的影片：用了什麼素材、做了哪些選擇、改了幾版、寫了哪些臨時程式 | 讓 AI 看到一個完整的實際例子 |

## 寫的時候要注意

- 通用做法和預設裡，用「講者」「旁白」「概念」這類一般的說法。人名、片名、秒數只放在範例。
- 不要寫只有某台電腦才有的東西，例如字型名稱、顯示卡型號、本機的檔案路徑。換一台電腦，這些都不一定存在。
- 每多做一支同類影片，就回來更新：補上新踩到的坑，刪掉被證明不好的做法，在範例加上這一支。
