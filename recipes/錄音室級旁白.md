# 旁白聲音規格：頂級 YouTube 工作室

用 TTS 加後製做出頂級工作室聽感的旁白規格。`helpers/prosody.py` 照這份處理節奏和換氣，`helpers/vocal_qc.py` 逐項量測；新聞短片（[sop/新聞短片.md](../sop/新聞短片.md)）用它驗收配音，其他產品線也可以沿用。

前提：

- **錄音間：** 經過聲學處理，殘響時間 RT60 < 0.3 秒，空調與電腦不在錄音間內。
- **器材：** 大振膜電容麥克風或 SM7B 類動圈麥克風，加防震架與防噴罩，嘴巴距離麥克風 8–12 cm。
- **前級與介面：** 乾淨的前級，24-bit / 48 kHz。
- **後製：** 由專業團隊處理，例如 iZotope RX 降噪、去唇齒音、換氣控制，再加上 EQ、壓縮與母帶處理。

以下規格是「成品聽起來應該長這樣」，不是「器材要買什麼」。我們用 TTS 加後製去模擬出這個結果。

| 項目 | 規格 | 理由與依據 |
|---|---|---|
| 整體響度 | −16 LUFS（±1） | Apple Podcasts 建議值；YouTube 會把響度正規化到 −14 LUFS，留 2 dB 不會被壓 |
| 真峰值 | ≤ −1.0 dBTP | 避免轉檔後破音 |
| 響度起伏（LRA） | 3–6 LU | 有起伏但不忽大忽小。純旁白的 podcast 一般落在這個範圍 |
| 底噪（停頓時） | ≤ −65 dBFS（RMS） | ACX 有聲書的上限是 −60；頂級錄音間在 −70 左右。底噪不該是數位全靜音，否則停頓會顯得「斷掉」 |
| 換氣聲 | 比說話低 24–30 dB（以最大聲的那一次計），每次 ≤ 0.35 秒，每分鐘 3–9 次 | 實測校正：上一版換氣只比說話低 13–18 dB、長 0.6 秒，你聽起來太大聲。專業後製通常把換氣壓低 6–12 dB，不會整個刪掉 |
| 換氣的位置 | 只在句號、問號，或較長的逗號停頓之前 | 真人只會在意群之間換氣 |
| 唇齒音、嘴巴雜音 | 聽不到 | 後製會用 De-click 處理 |
| 齒音（ㄙ、ㄘ、ㄕ） | 5–9 kHz 壓 3–6 dB | 清楚但不刺耳 |
| 噴麥、低頻 | 75 Hz 以下切除 | 等於防震架加高通濾波 |
| 音色 EQ | 250–350 Hz 削 1.5–2 dB（減混濁）、4 kHz +1.5 dB（咬字清楚）、10 kHz 以上 +1.5 dB（空氣感） | 常見的人聲後製曲線 |
| 動態處理 | 兩段式：輕壓縮 2:1（壓 2–4 dB，保留句與句的大小聲差），再用快速壓縮或限幅接住峰值 | 讓聲音「貼耳」、穩定 |
| 空間感 | 近距離的乾聲，加一層很淡的小房間尾巴：RT60 0.3 秒、比人聲低 20 dB（`prosody.py` 預設開，`--no-room` 關掉） | 近距離錄音的親密感要留著；但 TTS 的停頓是數位全靜音（約 −87 dBFS），完全乾的聲音每停一次都像訊號斷掉。真的錄音間 RT60 也有 0.2–0.3 秒，不是零 |
| 節奏 | 沿用韻律處理：關鍵句放慢、鋪陳句加快，停頓依標點分級 | 見 `helpers/prosody.py` |
| 切點 | 只在句子之間、音量最低的地方切，句子裡的逗號保留模型自己的語氣（`--chunk sentence`，explainer 語氣的預設）；切完淡出 40 ms（平滑曲線） | 逗號處模型常常沒有停，硬切會把字尾切掉。加速時同一句用同一個速度 |
| 斷點 | 每分鐘 ≤ 3 次（說話聲 30 ms 內掉到比說話低 40 dB） | 自然的收尾要 100–270 ms；30 ms 內就沒聲音，聽起來是「卡一下、訊號消失」。`vocal_qc.py` 量這一項，不合格時印出每個斷點的秒數 |

## 跟上一版比改了什麼

1. **不再用 [inhales] 標籤**，那就是刻意感的來源。只保留模型自然產生的換氣，並且依照上表的位置規則篩選。
2. **換氣處理：** 換氣聲取自同一個聲音先前的錄音（換氣素材庫），只放在句子之間；比說話低約 25–30 dB，長度最多 0.32 秒，開頭淡入 80 ms。
3. **底噪：** 約 −71 dBFS。
4. **後製鏈：** 改成上表的錄音室規格。
5. **驗收：** 每個成品都用 `helpers/vocal_qc.py` 量測，逐項對照上表。
6. **斷點（2026-11-22）：** 加上「切點」「斷點」兩項規格，「空間感」從完全乾聲改成乾聲加一層很淡的小房間尾巴。

## 踩過的坑

- **TTS 的停頓是數位全靜音。** ElevenLabs 的原始音檔，停頓時約 −87 dBFS，字音一收就掉進「沒有聲音」。原始音檔量起來每分鐘就有約 35 個斷點。只靠後製墊底噪（−71 dBFS）不夠，聲音還是會在 20 ms 內掉下去；要加小房間尾巴，讓每次收尾都自然消散。
- **在每個逗號切開會切到字。** 舊的韻律處理用「最後一個字的結束時間＋70 ms」當切點、淡出 12 ms。2026-11-22 的一份配音，99 刀裡有 28 刀切在聲音還沒收完的地方，每分鐘約 70 個斷點，聽的人說「卡一下」「好像訊號突然消失」。改成只在句子之間、音量谷底切之後降到每分鐘 2 個。
- **加速會讓收尾變短。** 一句加速到 1.3–1.45 倍，原本 30 ms 的收尾會壓成 20 ms。explainer 語氣把加速上限設在 1.3 倍。
- **換語氣可能會重新生成。** 快取的條件是「台詞文字＋TTS 設定」。news 語氣的 TTS 速度是 1.2，podcast、explainer 是 1.15；拿 1.15 的快取跑 news 會全部重新生成、花額度。只想調節奏時，用 TTS 速度相同的語氣。
- **耳朵聽到卡頓時，先量再改。** 用 `vocal_qc.py` 列出乾聲裡的可疑秒數，即使每分鐘的總數合格也逐一對回台詞。短暫的子音閉塞、標點停頓和音量突降都可能被標出，按原始音檔及剪接位置複核。背景音樂可能掩蓋乾聲的斷點，因此乾聲和成片兩邊都要查。

## 成片斷音 QA

1. 掃描整段未混樂的旁白，再檢查最終輸出的交接、音量與峰值。保存候選時間和對應台詞。
2. 把乾聲時間換算成成片時間。從候選秒數扣掉取用片段在源音軌的起點，再加上成片入點。命中使用者回報的台詞時，一起檢查逗號前的字尾和逗號後的字頭。
3. 源音連續而剪後中斷時，用同一份原音重做完整句子，收尾選在音量谷底。重新算字幕和分鏡時間，輸出後對照問題句及全片新一輪的候選點。
4. 黃仁勳辭任短片在「承認婚外情」和「由財務長暫代執行長」重現《浮點數 0.1 加 0.2》的逐逗號剪法問題。兩部片都以連續的原始句子復原句內接點。
