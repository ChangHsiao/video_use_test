# 整理型短片

把一集長訪談或 podcast 整理成一支 1～3 分鐘的直式短片。AI 讀完整集，挑一個主題寫成稿子，配音（TTS 或自己錄）當旁白，中間穿插講者自己說明重要概念的原話。

這份文件裡，「字卡」指疊在畫面上的文字（標題、重點），「圖解」指會動的圖。

## 適合／不適合

適合：

- 講者把概念講得很清楚的長影片，例如訪談、講座、知識型 podcast。要能從裡面挑出一個主題，單獨講完。
- 講者大多是正面的單人鏡頭。裁成直式之後，畫面還是完整的。

不適合：

- 重點在畫面上的影片，例如操作示範、旅遊。旁白會蓋掉原音，觀眾會看不懂畫面在做什麼。
- 多人你一句我一句的對談。很難找到一段能單獨聽懂的原話。
- 要公開發布，但沒有原作者授權的素材。這類短片大量使用別人的畫面和原話，發布前要先處理授權。

## 流程

1. **取得字幕。** 有沒有字幕都能做。原片有現成字幕（例如 YouTube 自動字幕）就先用，可以省下轉錄額度；沒有字幕就轉錄。YouTube 字幕可以用 yt-dlp 下載 json3 格式，裡面有每個字的時間；轉成 Scribe 格式的 JSON 之後，就能交給 `pack_transcripts.py`。轉錄會花額度，轉錄前要先問使用者。
   這是 Hard Rule 8 的例外：自動字幕有每個字的時間，但通常會拿掉口頭禪，時間也比 Scribe 不準。整理型短片只從原片挑幾段原話，剪點很少，所以可以接受；每個剪點多留一點空白，並用 `timeline_view` 確認沒切到字。如果要剪很多刀，或要剪掉口頭禪，還是要轉錄。
2. **列出內容地圖。** 讀完整份逐字稿，列出每個話題從第幾秒講到第幾秒。後面挑主題、找原話都會用到。
3. **挑主題。** 提出 2～3 個主題讓使用者選。一支短片只講一個主題。
4. **寫稿。** 每一句都註明出自原片的第幾秒，重要的句子回去對逐字稿，確認講者真的這樣說。只寫原片講過的內容；如果圖上要畫原片沒給數字的比較，要標「示意」。長度依稿子的語言估算每秒念幾個字，先配一段實際量過再修正，超過目標長度就刪句子。
5. **配音。** 先問使用者要用什麼配音：某個 TTS 服務的 API、到 TTS 網站生成後下載，或是自己錄。不管用哪種，都是一段稿子對應一個音檔。這樣某一段念錯時只要重做那一段，段落之間要空多久也能自己控制。如果語速太慢，可以用 ffmpeg 的 `atempo` 在本機加速，不會再花額度；範例經驗是 1.2 倍以內還算自然，實際能加速多少要請使用者聽過。
6. **挑講者原話。** 每一段配一句講者自己說明概念的話，開頭和結尾都切在安靜的地方。
7. **先檢查時間表再算繪。** 從 TTS 網站下載的音檔通常沒有每個字的時間，每句話從第幾秒開始要靠音檔裡的停頓去推算。先把每一句的開始和結束時間印出來檢查，確認沒問題才開始算繪。
8. **先畫示意圖確認版面。** 畫幾張靜止的畫面給使用者看，使用者同意之後才寫算繪程式。
9. **先算一小段，再算整支。** 改了東西之後，先看一格或幾秒鐘的片段；沒問題再出低解析度的整支預覽；使用者確認後，才算最終的解析度。範例曾經直接整支算了 6 分鐘，才發現背景太慢、動畫時間錯了。

## 預設（先問使用者）

- **講者原話每段大約十幾秒。** 理由：太短講不完一個概念，太長會拖慢節奏。
- **講者解釋概念，旁白負責其他部分。** 旁白講生活情境、方法和結尾。理由：概念由本人說最有說服力，旁白負責把內容串起來。
- **每一段的順序是：生活情境、概念、方法、為什麼有效。** 理由：觀眾要先覺得跟自己有關才會繼續看；講清楚為什麼有效，方法才讓人相信。範例那支只寫到方法，使用者看完覺得太空泛。
- **觀眾的注意力跟著聲音走，版面也跟著聲音換。** 旁白的時候，講者不是焦點：圖解和重點放在畫面中間，可以蓋住講者，背景調暗。講者說話的時候，他就是焦點：臉上不放任何東西，標題和圖解移到字幕下方，背景調亮。
- **背景一直用會動的原片畫面，不用靜止畫面。** 理由：靜止畫面看起來像投影片。剪接時讓「講者開口的那一格」剛好接上他的聲音；旁白時講者嘴巴在動沒關係。
- **圖解要會動，跟著旁白念到的時間出現或變化。** 例如講到「很低」的時候，量表的指針才滑過去。理由：畫面和聲音同步，觀眾比較跟得上。
- **字幕要大，放在下巴到胸口之間。** 理由：手機上看得清楚，也不會擋到臉。

## 踩過的坑

配音：

- **同一個字有不同念法時，TTS 容易念錯。** 例如中文多音字、日文漢字的讀音、英文縮寫和專有名詞。範例：ElevenLabs Multilingual v2 把「幹勁」念成「乾淨」（2026-10）。每段配完都要請使用者聽一次，念錯就換模型，或把那個詞改成不會念錯的說法。
- **TTS 服務的方案和權限會限制能做的事。** 開始配音前，先和使用者確認他的方案現在能做什麼；下面是 2026-10 實測的情況，可能已經改變。
  - ElevenLabs 免費方案不能用 API 呼叫聲音市集（Voice Library）的聲音，只能到網站上生成再下載。
  - ElevenLabs 的 API key 有權限範圍，「文字轉語音」要打開。
  - edge-tts（非官方的免費工具）回傳 403 錯誤，不能用。
- **不要複製真人講者的聲音。** 沒有本人同意，TTS 服務的條款通常也不允許。用服務裡現成的聲音。

時間：

- **從停頓推算出來的句子時間會差零點幾秒。** 切點要移到真正的停頓裡，不然會切到字。
- **每一句各自找最近的停頓，可能會出問題。** 有的句子會只剩 0.01 秒，字幕一閃就不見。要把整段的句子一起考慮，找出整體最合理的切法（範例用的是動態規劃），再檢查每一句的語速是否合理。

算繪：

- **先量是哪一步慢，再決定改哪裡。** 範例原本以為慢在字卡，量了才發現慢在背景的亮度混合。
- **逐格合成的程式裡，用 lambda 描述每個元素的動畫時，用預設參數綁住當下的值**（`lambda t, lt=lit_t: ...`）。範例每一段都用同一個變數名稱，前面的圖解全都讀到最後一段的時間。

## 加快算繪

這一段的秒數都是範例那台電腦用 CPU 編碼量到的，只能用來比較快慢。

- **所有疊在影片上的東西，在 Python 裡合成成一層再交給 ffmpeg。** 字卡、圖解、暗色遮罩都在 Python 裡逐格畫成一張透明圖，透過管線（pipe）直接送進 ffmpeg，只疊一次；畫面沒變的格就重用上一格。不要把幾十張 PNG 各自當成一個從頭到尾的圖層交給 ffmpeg，那樣會非常慢。範例 5089 格裡只需要重畫 500 格。
- **背景變暗用半透明黑色遮罩，不要用逐像素的混合。** 背景一律用同一種亮度輸出，旁白時要變暗，就在上面那一層疊一層半透明的黑色。範例的背景處理從 294 秒降到 40 秒。
- **修改階段出低解析度預覽，最後才出全尺寸。** 範例的 540×960 預覽約 2 分鐘，1080×1920 成品約 6 分鐘。
- **硬體編碼不一定能用。** 先試一次，不能用就改用 libx264。

## 還沒解決

- **旁白容易寫得太長、太空泛。** 範例每段只講了情境和方法，沒講為什麼有效。重寫時，要讓每一段都有一個觀眾原本不知道的資訊。改稿之後，配音、時間表和圖解出現的時間都要重新算。
- **圖解出現的時間不一定準。** 範例是照字數比例推算旁白念到哪裡，可能早或晚零點幾秒，沒有逐一聽過確認。

## 範例

### 四種大腦化學物質的使用說明書（2026 年 10 月）

- **參考的成品**：YouTube Shorts `IrNCV6MsHQA`。深色字卡、開場提問、結尾字卡，出處寫在影片說明欄。
- **素材**：Huberman Lab Essentials（YouTube `xKvlK7OqZso`），30 分 51 秒，英文，用 YouTube 自動字幕，沒有轉錄。
- **主題**：四種神經調節物質（多巴胺、腎上腺素、乙醯膽鹼、血清素）各自管什麼，以及怎麼不靠藥物提升。
- **配音**：在 ElevenLabs 網站生成，聲音是 Kuo Yu（台灣腔），模型 Eleven v4，共 6 段，下載後加速 1.15 倍。整份稿子大約用掉 850 點額度。
- **稿子長度**：中文用每秒約 4.5 個字估算。
- **使用者的風格選擇**：
  - 旁白念到概念名稱時，畫面中間出現黃色大字；講者原話一開始，換成下方的大標題，當作這一段的名牌。
  - 畫面最上方固定一行小標題，開場不放，因為開場本身就是標題。
  - 原話不加「原話」標籤，保留原片本身的近景和遠景切換。
  - 不放「整個人沒電？」這類情境句的黃字，使用者覺得沒有必要。
- **成品**：2 分 50 秒，共 17 個片段（旁白 12 段、講者原話 5 段）。
- **改了四版**：
  - v1：只有字卡。
  - v2：加入講者原話。
  - v3：背景改成連續的原片，字卡移到畫面下方。
  - v4：加入會動的圖解，版面照「注意力跟著聲音走」的原則調整。
- **寫了哪些臨時程式**：
  - 把 YouTube 字幕轉成 Scribe 格式的 JSON。
  - 查 TTS 剩餘額度和可用的聲音。
  - 產生字卡圖片。
  - 畫圖解，每個圖解的函式說明裡寫了它怎麼動。
  - 排時間軸、接音訊、準備背景影片。
  - 逐格合成並算繪。有兩個選項：只出低解析度預覽，以及只印出時間表不算繪。
