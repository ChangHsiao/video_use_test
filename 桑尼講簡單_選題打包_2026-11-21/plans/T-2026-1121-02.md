## 一句承諾

看完會懂手機臉部與指紋解鎖到底在比對什麼、Apple 公布的『百萬分之一』是什麼意思、為什麼照片不行雙胞胎卻有機會，並知道什麼情況該關掉臉部解鎖、為什麼密碼仍然要設得夠強

## 開場鉤子

- **畫面**：關鍵畫面：桌上一支 iPhone，一隻手拿著 A4 列印的大頭照慢慢靠近前鏡頭，畫面上方的鎖頭圖示（結果以實拍為準）；切黑底字卡『照片騙不了它。』→ 再切 Apple 官方文件句子重點標黃『雙胞胎……機率較高』。
- **口白**：口白：『拿我的照片，能不能打開我的手機？我們先試給你看。——那換成長得跟我一模一樣的雙胞胎呢？連 Apple 自己都寫：有機會。手機到底記住了我臉的什麼？為什麼它這麼準，卻還是一定要你設密碼？我是桑尼，今天把臉部解鎖講簡單。』

## 摘要

以『拿自己的照片能不能解開自己的手機』實測開場，依 Apple 官方文件說明 Face ID 用光點深度圖與紅外線影像轉成數學表示比對、平面照片缺乏深度；再用門檻天平解釋所有生物辨識都是誤認與誤拒的取捨，搭配 Apple 公布的百萬分之一、五萬分之一等機率與 Android 的 FAR／SAR 分級；反轉說明雙胞胎、手足與 13 歲以下兒童為何例外、為何開機與多次失敗一定要密碼；收在『誤判成本由誰承擔』的工程觀點與實用設定清單。

## 五面向企劃

### 1. 主題與核心問題

- **談誰／什麼**：談手機生物辨識的運作與極限：①怎麼看——Apple 支援文件 102381（已讀，2026-09-18）：TrueDepth 相機投射並分析數千個看不見的光點建立臉部深度圖，同時拍一張紅外線影像，由 Secure Enclave 保護的神經引擎轉成『數學表示』後跟登記資料比對；Face ID 一定需要深度資訊，平面照片沒有；並以反偽冒神經網路防面具等手法；具注意力感知（要睜眼看）。②有多準——Apple Platform Security（已讀）：隨機一人解鎖機率 Face ID／Optic ID 低於百萬分之一，Touch ID 低於五萬分之一；登記 5 根手指時升到最高萬分之一、Face ID 兩種外貌最高五十萬分之一；連續 5 次失敗就要密碼；雙胞胎、長相相似的手足、13 歲以下兒童誤判機率較高。③怎麼量——Android 開源專案《Measure biometric unlock security》（已讀）：用 FAR（隨機錯人被接受）、SAR（偽冒樣本被接受）、IAR（模仿者被接受）三種指標；Class 3 要求 FAR 1/50k、FRR 10%、各類偽冒 SAR 上限；Class 1 不能提供 API 給 App 使用。④為什麼還要密碼——Apple：使用 Face ID 必須先設密碼；剛開機、超過 48 小時未解鎖、5 次失敗等情況一定要輸入密碼；Face ID 資料不離開裝置、不備份到 iCloud。
- **最想解釋**：最想解釋：臉部解鎖不是『認出你是誰』，而是『這張臉跟登記的那份數學摘要像不像，像到超過門檻就放行』——所以它本質上是機率題；門檻設嚴，自己常被擋（誤拒），設鬆，別人可能被放行（誤認）；工程師用 FAR／FRR 這兩把尺找平衡，再用『5 次失敗就要密碼』『開機一定要密碼』把風險關在小範圍內——密碼才是總鑰匙，臉和指紋是方便鑰匙。
- **主張**：影片主張：Face ID 很安全，但『安全』指的是『隨機陌生人百萬分之一』這種有條件的機率，不是『只有你能開』；照片騙不了是因為它要的是深度，雙胞胎有機會是因為統計上長得太像；理解『機率＋門檻＋後備密碼』這套設計，你就知道什麼情況該關掉臉部解鎖、為什麼密碼仍然要設得夠強。
- **研究方向**：研究方向：Apple 支援 102381 英文與繁中版（已讀全文：數千光點、深度圖＋紅外線影像、百萬分之一、雙胞胎與 13 歲以下、需深度資訊、反偽冒、注意力、何時要密碼、資料不離開裝置、部分相機可看到紅外光）；Apple Platform Security『Optic ID, Face ID, Touch ID, passcodes, and passwords』網頁版與 PDF（已讀相關段：五萬分之一、萬分之一、五十萬分之一、5 次）；Apple 2017-11《Face ID Security Guide》PDF（200，讀摘要：當時寫『約百萬分之一 vs Touch ID 五萬分之一』）；AOSP《Measure biometric unlock security》（已讀：FAR／SAR／IAR、Class 1–3 表）；Android CDD（200，未細讀）；Android Developers《Show a biometric authentication dialog》（200，未細讀）；Google Pixel 說明 9517039（已讀）；YouTube：Insider Tech 2017-11-13《Using An Infrared Camera To Show How Face ID Works》（1:39，說明欄寫『超過 30,000 個點』——屬第三方說法）、WSJ 2017-11-02《iPhone X Review: Testing (and Tricking) FaceID》（4:09，說明欄：以面具、裝扮與同卵三胞胎測試）、Insider Tech 2017-10-31 雙胞胎測試（1:47）、啾啾鞋 2017-07-29 指紋辨識（4:28，繁中競品）——全部只看中繼資料與說明欄，未觀看。
- **故事主線**：故事主線：開場——手機放桌上，桑尼（或手部）拿一張自己的列印大頭照對著自己的 iPhone（實測，結果以實拍為準；Apple 文件說 Face ID 需要深度資訊）→ 『為什麼照片不行？那雙胞胎呢？』→ 第一層：手機到底看到什麼——光點深度圖＋紅外線影像（動畫；若手邊相機能拍到紅外光點則實拍，Apple 文件提到部分相機會看到 TrueDepth 的光，待實測）→ 第二層：它不是存你的照片，是存一份『數學摘要』，比對像不像（動畫：兩張臉變成兩串數字，算距離）→ 第三層：所有生物辨識都是機率題——FAR／FRR 天平動畫：門檻往左，你自己常被擋；往右，陌生人可能進來；Apple 公布的數字：Face ID 百萬分之一、Touch ID 五萬分之一，登記越多指紋機率反而變高（萬分之一）→ 第四層：為什麼雙胞胎、小孩例外——統計上的『像』；Android 用 SAR 專門量『偽冒樣本』被接受的機率，Class 1 不准給 App 用（只講分級概念，不教偽冒方法）→ 第五層：所以密碼是總鑰匙——開機、48 小時、5 次失敗一定要密碼（錄螢設定頁）；資料不離開手機→ 收束：工程師觀點——任何『判斷』系統（包含 AI）都有誤判，好的設計是先決定誤判成本由誰承擔，再設門檻與後備方案；行動：家裡有長得像的手足或小孩、或擔心被趁睡著解鎖時，改用密碼或關閉臉部解鎖；密碼設長一點。
- **核心問題**：手機看我一眼就解鎖，它到底記住了我臉的什麼？拿我的照片可以騙過它嗎？我的雙胞胎兄弟能不能解開？既然臉這麼準，為什麼重開機還是一定要打密碼？

### 2. 觀眾與先備知識

- **給誰**：一般大眾（每天用臉或指紋解鎖、用手機付款的人）；次要：家長（小孩用手機）、雙胞胎或手足、剛開始做 AI 判斷類產品的非工程師。
- **先備知識**：先備：會用手機解鎖即可；不需要懂機器學習或統計（以『數學摘要』『門檻天平』『方便鑰匙 vs 總鑰匙』比喻補上）。
- **解釋深度**：解釋深度：只講深度＋紅外線取樣、數學表示比對、FAR／FRR 門檻、偽冒（SAR）概念、密碼作後備五件事；術語保留 Face ID、Touch ID、TrueDepth、Secure Enclave、FAR、FRR，各附白話；不講神經網路結構與加密細節；不教任何偽冒手法；所有機率只用 Apple／Android 官方公布數字並標『官方宣稱』。
- **痛點**：不確定臉部解鎖安不安全；聽說照片或雙胞胎能騙過手機；小孩或手足長得像擔心被解鎖；不懂為什麼重開機一定要輸密碼、覺得很煩；分不清不同手機的臉部解鎖安全等級是否一樣
- **開場鉤子風格**：開場鉤子：一張列印的大頭照對準手機前鏡頭，畫面上鎖頭圖示不動（以實拍為準）→ 字卡『照片騙不了它』→ 下一格字卡『但 Apple 自己說：雙胞胎機率比較高』→ 『為什麼？』

### 3. 觀看後的改變

- **理解**：理解：Face ID 以深度圖＋紅外線影像轉成數學表示比對；生物辨識是機率比對，有誤認（FAR）與誤拒（FRR）兩種錯；官方數字是『隨機陌生人』條件下的機率；雙胞胎、手足、13 歲以下兒童不適用該數字；Android 依偽冒與誤認率把生物辨識分級；密碼是開機與多次失敗後的後備總鑰匙。
- **重新思考**：重新思考：『很安全』永遠要問『對誰、在什麼條件下』——百萬分之一擋得住路人，擋不住長得像的家人；方便與安全是同一個門檻的兩端。這也是所有 AI 判斷系統的共通課題：不存在零誤判，只有『誤判了怎麼辦』的設計。
- **行動**：行動：有長得像的手足、或小孩會拿你手機時，考慮改用密碼（Apple 與 Google 官方都這樣建議）；把裝置密碼設成 6 位以上或英數混合；需要時可關閉『戴口罩使用 Face ID』或開啟『需要注視』；Android 使用者到設定查看臉部解鎖能否用於 App 驗證（能否用於付款代表安全等級不同，依機型而定）。
- **段落目的**：照片騙解鎖 Hook（共同疑問＋實拍）→光點深度與紅外線（原理一）→數學摘要比對（原理二）→FAR/FRR 門檻天平與官方機率（主體＋工程師觀點）→雙胞胎、小孩與 Android 分級（反轉）→密碼是總鑰匙（實用）→誤判成本設計＋行動清單（收束）。
