# 新聞短片

| 項目 | 內容 |
|---|---|
| 適用範圍 | 把公開報導、當事人說法和正式公告整理成約 2 分鐘的直式新聞解說短片（YouTube Shorts、Reels）。結構是「旁白鋪陳 → 原聲佐證」交替。給 Agent 照著做 |
| 相關文件 | 新聞怎麼取捨、怎麼排：[recipes/時事新聞短影音.md](../recipes/時事新聞短影音.md)<br>畫面規則：`styles/<風格名稱>/STYLE.md`，預設是[桑尼新聞短片](../styles/桑尼新聞短片/STYLE.md)<br>品牌規則（片尾、口播收尾）：[brands/桑尼資料科學/BRAND.md](../brands/桑尼資料科學/BRAND.md)<br>配音規格：[recipes/錄音室級旁白.md](../recipes/錄音室級旁白.md) |
| 狀態 | 試行版，2026-11-22 依 EP.01（黃仁勳辭任）的做法整理。確認點沿用科普短片的節奏，還沒用第二集驗證 |

`<skill>` 指這個 repo 的位置（通常是 `~/.claude/skills/video-use`），`<edit>` 指這一集的 `<影片資料夾>/edit/`。工具一律從 `<skill>/helpers/` 執行，不複製到影片資料夾。新聞工具需要額外套件：`uv sync --extra news`（在 `<skill>` 執行一次）。

## 確認點

| # | 時機 | 給使用者看什麼 | 使用者回什麼 |
|---|---|---|---|
| 1 | 開始 | 素材清單：每支來源影片的檔名、長度、出處；缺逐字稿時一次問完怎麼取得 | 確認素材沒有漏 |
| 2 | 編輯判斷做完 | 企劃：「截至＿＿，最重要的新事實是＿＿，看完能回答＿＿」、事件短表、敘事結構（倒金字塔或沙漏式）、封面兩種角度、片名、配音聲音 | 「好」或指定要換的項目；配音聲音一定要明確回答 |
| 3 | 台詞和分鏡寫完 | `voice/台詞_short.txt`、`短片.json` 的鏡頭清單（每個鏡頭的來源和秒數） | 「好」，或指出要改的句子、畫面 |
| 4 | 合成整支片之前 | `news_short.py --samples` 的樣張（標題、資訊卡、原聲卡、字幕、封面）和配音檢查結果 | 「好」，或指出要改哪一張 |
| 5 | 成品 | 成品、審稿結果、發布資料 | 「好」，或提修改意見 |

會花額度的動作（轉錄、配音、AI 封面）一定先問，不管在不在確認點。

## 步驟

### 1 素材

照 [科普短片的第 1、2 步](科普短片.md#1-素材2-逐字稿)取得來源影片和逐字稿。每支來源記下 YouTube 標題和網址，發布資料要用。

### 2 編輯判斷

照 [時事新聞短影音](../recipes/時事新聞短影音.md) 的「先做編輯判斷」「選敘事結構」：寫下這一集要回答的問題，把素材排成事件短表（日期、哪一方做了什麼、直接來源、證據狀態、可用畫面），選倒金字塔或沙漏式。
**交出什麼**：確認點 2 的企劃，存成 `<edit>/企劃.md`。

### 3 台詞

寫 `<edit>/voice/台詞_short.txt`。格式是 `句號|念的文字|字幕中文|字幕英文`，用 `## 段名` 分段，每段是一個旁白區塊。口播收尾不寫進台詞（用品牌的固定音檔）。
**怎麼檢查**：每項指控都寫明出處（「據報導」「被懷疑」）；數字都找得到原句。

### 4 配音

```
uv run --project <skill> --extra news python <skill>/helpers/prosody.py --edit <edit> --voice-dir /home/sunny/Videos/聲音範本/A1_男聲 --tag short_A1 --profile news --chunk sentence --script <edit>/voice/台詞_short.txt --sections 0,1,...
uv run --project <skill> python <skill>/helpers/vocal_qc.py <edit>/voice/錄音室版/short_A1_rhythm.mp3
```

**交出什麼**：`<edit>/voice/錄音室版/short_A1_rhythm.mp3` 和 `short_A1.json`（每句的時間，分鏡要用）。
**怎麼檢查**：`vocal_qc.py` 每一項都是 OK。

### 5 分鏡

寫 `<edit>/短片.json`，格式見 `helpers/news_short.py` 開頭的說明。

- 旁白區塊（`vo`）的每個鏡頭用 `line` 指定從第幾句開始；原聲區塊（`sot`）寫來源影片的起訖秒數和逐句字幕。
- 最後一個區塊是口播收尾：`{"signoff": {"audio": "<brand.json 的 signoff.audio 解析成完整路徑>", "show": ..., "en": ...}, "shots": [...]}`，文字照 `brand.json` 的 `signoff`。
- 片尾：`"outro": {"video": "<品牌 assets/outro_A_3s.mp4 的完整路徑>"}`。
- 分鏡裡的相對路徑都從 `<edit>` 算；品牌素材寫完整路徑，不要複製一份到影片資料夾。

### 6 樣張和合成

```
uv run --project <skill> --extra news python <skill>/helpers/news_short.py <edit>/短片.json --samples
uv run --project <skill> --extra news python <skill>/helpers/news_short.py <edit>/短片.json --out short_v1.mp4
```

`--samples` 把每種疊加層各輸出一張到 `<edit>/verify/`，給確認點 4 看。風格不是預設的「桑尼新聞短片」時加 `--style <名稱>`。

### 7 審稿（必做）

按照 [品質檢查表的聲音檢查](品質檢查表.md) 複查整支成片。旁白和混音都要掃描；把可疑秒數對回台詞、配音原檔和剪接點，特別檢查逗號後第一個字、新聞原聲進出點和片尾交接。

成片交給使用者之前，派一個審稿 sub-agent，逐鏡頭抽格檢查：

1. 畫面和旁白是否對得上。
2. 隱私與指控：當事人中不該露臉的人不能出現，也不能被點名；指控一定要寫明出處，例如「據報導」「被懷疑」。新聞台的跑馬燈如果把指控寫成事實，要裁掉。
3. 關鍵句前後：講到「那名女子」「高階主管」這類字眼時，畫面上不能剛好出現身分不明的人，觀眾會誤認。
4. 原畫面帶有聲明、標題或資料圖時，對照來源抽看片頭、片中和片尾的該鏡頭，確認必要文字和數字在安全範圍內。若直式裁切會截斷，先用 `fit: true` 等比置入，再依該鏡頭確認跑馬燈的裁切高度。
5. 原聲字幕和講話是否同步。

EP.01 抓出來的嚴重問題，都屬於第 3 項。

### 8 發布資料

格式參考 `/home/sunny/Videos/黃仁勳辭任/edit/design/發布資料.md`（Linux），片名格式見風格的「預設值」：

- 片名
- 說明欄：
  - 一段話摘要，每項指控都寫出處
  - 本集提問
  - 註記：指控未經證實、動畫為示意圖
  - 系列句
  - 原聲與畫面來源（每支來源影片的 YouTube 標題和網址）
  - 資料來源
  - hashtag
- 置頂留言：放本集提問，不用表情符號

發布後的觀察和下一集要改什麼，照 [時事新聞短影音](../recipes/時事新聞短影音.md) 的「怎麼從一集累積成經驗」。
