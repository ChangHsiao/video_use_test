這份只管「看起來、動起來的樣子」。內容的規矩（每句要有出處、說明動畫要標「示意圖」）寫在流程文件，不管選哪種風格都要遵守。

**這是學畫面語言，不是複製頻道。** 不用 3Blue1Brown 的吉祥物（π 角色）、標誌、頻道名稱，不複製它的程式碼（影片原始碼是 CC BY-NC-SA 授權，這裡只整理做法，用自己的話和自己的程式寫）。成片不要寫「3Blue1Brown 出品」這類讓人誤會的字。

## 一句話

**全黑的底上，一次只講一件事；每個新東西都從畫面上已經有的東西長出來；顏色代表概念，不是裝飾；動完就停下來讓人看。**

## 固定的規則

### 畫面

| 項目 | 規則 |
|---|---|
| 底色 | 純黑 `#000000`。不用漸層、格線、紋理、暗角 |
| 質感 | 平面：不加陰影、發光邊框、圓角卡片、玻璃效果、介面外框。唯一的發光是「沿著曲線跑的那個點」 |
| 字型 | 襯線體（原本是 CMU Serif）。中文用思源宋體（Noto Serif TC），字重一般，不用粗體。等寬字只用在位元、程式碼 |
| 線條 | 細：圖形外框 1、一般線 2、重點線 3，最粗不超過 5。座標格線寬 1、不透明度 0.25–0.5 |
| 文字量 | 少。標題 1–3 個詞，標籤 1–2 個詞，問題一句。不做條列投影片；標籤貼在它說明的東西旁邊，不另外放圖例 |
| 壓在圖上的字 | 加黑色描邊（寬 3–8），不加底色方塊 |

### 顏色

| 顏色 | 色碼 | 只用在 |
|---|---|---|
| 黃 | `#FFFF00` | 「現在看這裡」：外框、掃過的閃光、被點名的那一項 |
| 藍 | `#58C4DD` | 主要的對象、正的值、被命名的概念 |
| 青綠 | `#5CD0B3` | 正在作用、正在流動的東西 |
| 紅 | `#FC6255` | 錯誤、被擋下來、負的值 |
| 綠 | `#83C167` | 正確、通過 |
| 粉紅 | `#D147BD` | 需要第五個概念色時才用 |
| 白、灰 | `#FFFFFF`、`#DDDDDD`、`#BBBBBB`、`#888888`、`#444444` | 文字、資料本身、座標軸、次要的東西 |

- **一個概念固定一個顏色，整支片不換。** 寫分鏡前先列「概念 → 顏色」對照表（例如 查詢＝黃、鍵＝青綠、值＝紅）。公式裡的符號和圖上對應的東西同色。
- 一個畫面同時出現的概念色不超過 3 個。資料、數字本身用白或灰，只有「它是什麼」才上色。
- 漸層色只用來表示數值（例如熱度圖），不拿來裝飾。
- 不透明度分層：主角 1；上一步的東西 0.5；沒被選到的 0.35；背景脈絡 0.2–0.25；快要退場 0.1。重點框的填色 0.15–0.25。
- 成片的飽和度拉高到 1.5 倍（原始碼的設定）。Manim 算繪的動畫合成時才做一次，不要重複做。

### 版面

| 項目 | 規則 |
|---|---|
| 標題 | 靠上，可以加一條細底線；講到某個概念的名字時用它的概念色 |
| 主圖 | 放正中間，四周留白。左邊放「機器、過程」，右邊放「結果」；直式畫面改成上面過程、下面結果 |
| 公式 | 釘在上緣或角落，不蓋住主圖；主圖旁邊的公式比標題小一級 |
| 間距 | 標籤貼著東西（0.1–0.25 個單位），區塊之間 0.5，離畫面邊緣至少 0.5 |
| 舊的內容 | 縮小移到角落，或調暗留在原地，不要直接消失。真的要清場時，全部一起錯開淡出（每個差 0.1） |
| 外部影片、圖片 | 細白框（寬 1–2）加一行標題或一行出處，不加陰影、圓角 |

### 動畫

用哪種動作，照「這個東西和畫面上已有的東西是什麼關係」決定：

| 情況 | 動作 |
|---|---|
| 全新的東西出現 | 淡入，帶一點位移（0.2–0.5 個單位，往它要去的方向） |
| 文字、公式出現 | 像手寫一樣描出來（Write）：短的 1 秒，15 個字以上 2 秒 |
| 線、框、曲線出現 | 從頭畫到尾 |
| 從已有的東西得出來的結果 | **複製一份變過去**（TransformFromCopy）：原來的留著，新的從它身上長出來。這是這個風格最重要的動作 |
| 同一個東西換個樣子 | 直接變形，沿著弧線移動（約 45°） |
| 公式改寫 | 相同的符號滑到新位置，只有不同的部分淡入淡出 |
| 一排類似的東西 | 依序錯開進場。5–10 個時每個差 0.25，幾十個時差 0.01–0.05，整組 2–3 秒做完 |
| 參數在變 | 用一個數值帶動整張圖一起連續變化，來回掃一次 3–6 秒 |
| 強調 | 見下一張表 |

強調只用這幾種，由輕到重：

| 手法 | 做法 |
|---|---|
| 黃色細框 | 寬 2、離內容 0.05–0.25；講到下一項時，**同一個框移過去**，不要消失再出現 |
| 把其他的調暗 | 其他東西降到 0.35，講完再恢復 |
| 沿著外框掃一圈光 | 2–3 秒，用在「就是這個」的那一下 |
| 顏色閃一下再變回來 | 整個過程 1–2 秒 |
| 大括號加說明 | 指出「這一段是什麼」 |
| 彎的箭頭 | 表示「指的是它」「從這裡來」，彎 90°–150° |
| 局部放大 | 鏡頭推近，看完再退回來 |

不要做：

- 彈跳、回彈、放大蹦出來、旋轉飛入、擦除轉場
- 場景裡面硬切（硬切只發生在兩個場景之間，而且前一個場景是停住的）
- 淡出到黑、交叉溶接
- 整個畫面一起動卻沒有東西可以看；鏡頭自己晃

緩動一律用「慢 → 快 → 慢」的平滑曲線。只有計數器、模擬時間、等速旋轉用等速。

### 節奏

| 項目 | 規則 |
|---|---|
| 一拍 | 一個動作 1–2 秒，然後**停 1 秒以上**。每個動作後面都要停，停的時候旁白在講 |
| 複雜的變形 | 2–4 秒 |
| 重複的過程 | 第一次慢慢做（每步都停），第二次快一點，之後一口氣跑完 |
| 先具體再一般 | 先用一個實際的數字、實際的句子跑一遍，再換成符號 |
| 一個場景 | 只講一個想法。分鏡表一個場景一筆，照敘事順序排 |
| 開場 | 直接從主角的圖開始，不放標題卡 |
| 結尾 | 停在最後的重點上（至少 2 秒），不淡出 |
| 長的展示 | 模擬、旋轉展示可以放 15–30 秒不打斷，讓旁白講 |
| 鏡頭 | 平面的圖幾乎不動：只做單一方向的平移、推近再退回，而且和內容的動作同時進行。立體的圖從正面開始，花 3–5 秒轉到斜角，之後每秒 1–2.5° 慢慢轉，要做下一個動作前先停 |

### 常用的圖

需要畫這些東西時，照這個樣子畫，整支片一致：

| 東西 | 畫法 |
|---|---|
| 一個詞、一個 token | 細白框的小方塊，深灰半透明填色，字在中間 |
| 向量 | 一直行數字，左右加方括號 |
| 矩陣、表格 | 細線格子（線寬 1），正的值藍、負的值紅，深淺表示大小 |
| 神經網路 | 一排排小圓點，連線很細很淡，啟動的點變亮 |
| 一層一層的處理 | 疊起來的薄板，資料經過時那一層閃青綠色 |
| 機率、比例 | 橫的或直的長條，旁邊標數字 |
| 流程 | 輸入 → 方塊 → 輸出，從左到右（直式改成從上到下） |
| 函數圖 | 座標軸很淡、刻度很少，曲線線寬 2–3、單一顏色，一個發光的點沿著曲線走 |
| 曲線下的面積 | 同色、不透明度 0.5 |

### 會插進來的短鏡頭

| 鏡頭 | 做法 | 多常用 |
|---|---|---|
| 觀眾的疑問 | 黑底上一句問句（把觀眾心裡的「等等，為什麼？」講出來），3–8 秒。原本由吉祥物演，這裡改成純文字或講者 | 每 4–6 個場景一次 |
| 章節標題 | 一行大字靠上，寫出來，停住 | 換大段落時 |
| 路線圖 | 這支片的 2–3 個段落並排，講過的調暗到 0.5 | 長片才用；短片不用 |
| 一句話、引文 | 靠左對齊，出處用灰色小字 | 需要時 |
| 清單 | 一次出一項；講到的放大到 1.25 倍，講過的降到 0.5 | 盡量少用 |

## 用在直式短片時的調整

3Blue1Brown 的影片都是橫式（16:9、4K、30 格），沒有直式版本，也不把字幕做進畫面。用在這個專案的 1080×1920 短片時，下面這些是**這個專案自己加的**，不是從原始碼學來的：

| 項目 | 做法 | 理由 |
|---|---|---|
| 構圖 | 左右排的東西改成上下排；一個畫面只放一張圖 | 直式畫面寬度只有橫式的一半 |
| 字級 | 以畫面寬 8 個單位計：標題 44、內文 32、標籤 24、小字 18（Manim）。疊加層的字級沿用 `style.json` | 橫式的 72／48／36 放進直式會爆框 |
| 字幕 | 中文白色、第二語言灰色 `#BBBBBB`，位置和其他風格一樣 | 黃色保留給「看這裡」，字幕不能搶 |
| 頂部標題 | 白色，重點字黃色 | 同上 |
| 數字卡 | 大數字白色，或用那個數字所屬概念的顏色 | 顏色代表概念 |
| 段落標題卡 | 純黑底，小標灰、大標藍 | 對應「章節標題」 |
| B-roll | 背景比暗色科技風更暗（亮度 25%） | 接近黑底，和動畫切換時不會跳 |
| 疊加層的字型 | 沿用系統黑體（`compose.py` 的預設）；要襯線體時用 `--font` 指定字型檔 | 小字級的襯線中文在手機上不好讀。沒有實測過 |

## 預設值

這些項目每支片可能不同，但不逐項問使用者：Agent 把預設值整理進企劃（流程的確認點 2），使用者一次看完，沒意見就照用。講者、配音聲音照流程文件的規定，一定要使用者明確回答。

| 項目 | 預設值 | 理由 |
|---|---|---|
| 頂部標題 | Agent 推薦 1 個，附 2 個備選；用「為什麼」「怎麼做到」的問句 | 這個風格是從一個問題出發，一路解到底 |
| 口吻 | 第一人稱、帶著觀眾一起想：「我們先看一個小例子」「你可能會問……」。不吐槽、不喊口號 | 和畫面的節奏一致 |
| 動畫和 B-roll 的比例 | 動畫為主（一半以上的時間）；B-roll 只在需要看到實物時用 | 這個風格靠圖講道理 |
| 動畫引擎 | Manim（照 [manim.md](manim.md)）。內容不是數學、圖形類，或要沿用零件庫時，用 Remotion 加 `theme.ts` | Manim 的變形、描字是這個風格的原生動作 |
| 概念色對照表 | Agent 在企劃列出這支片的 2–4 個概念各用什麼顏色 | 使用者一眼能看出配色有沒有道理 |
| 字幕語言 | 中英雙語 | 和專案其他風格一致 |
| 旁白語速 | `prosody.py --profile explainer`：含停頓約 5.9 音節/秒，介於 podcast（4.5）和新聞（7.3）之間；只在句子之間切、加小房間尾巴。驗收照 `recipes/錄音室級旁白.md`，`vocal_qc.py` 的 dropouts 每分鐘 ≤ 3 | 這個風格是講完一步停一下，太慢會拖、太快跟不上畫面。2026-11-22 測試片：podcast 238 秒、explainer 179 秒（同一份稿子） |
| 配樂 | 不放，或很輕的鋼琴／弦樂墊底 | 原始影片的動畫是無聲算繪，聲音後製時才加；旁白是主角 |
| 講者 | 沒有預設，問使用者。沒有講者時，「觀眾的疑問」用純文字鏡頭 | 見流程文件 |

## 交片前多看這幾項

`sop/品質檢查表.md` 之外，這個風格再加：

1. 抽 5 個畫面：底是不是純黑；有沒有陰影、圓角卡片、漸層混進來。
2. 概念色對照表：同一個概念從頭到尾同一個顏色；黃色只出現在「看這裡」。
3. 每個新東西是不是從畫面上已有的東西長出來的；有沒有憑空蹦出來的結果。
4. 每個動作後面有沒有停；有沒有連續三個動作中間沒停。
5. 有沒有彈跳、擦除、淡出到黑。
6. 場景結尾是不是停在重點上。
7. 一個畫面的字有沒有超過「一個標題加三個標籤」。

## 分析依據

數字來自對 `_2023`–`_2026` 資料夾 118 個場景檔的統計，以及 manim 函式庫的預設值。

| 觀察 | 數字 | 變成哪條規則 |
|---|---|---|
| 最常用的動畫 | 淡入 2771 次、淡出 2474、描字 1238、畫線 990、複製變形 862、依序錯開 1353；「搖一下強調」只有 26 次 | 進場用淡入和描字；結果用複製變形；不靠晃動強調 |
| 動作時間 | 最常見 2 秒，再來 3、1、5、4、1.5 秒 | 一個動作 1–2 秒，複雜的 2–4 秒 |
| 停頓 | 5932 次停頓，其中 4154 次是預設的 1 秒 | 每個動作後停 1 秒以上 |
| 錯開的間隔 | 最常見 0.1；函式庫預設 0.05 | 清場、文字用 0.1；數量少時放寬到 0.25 |
| 緩動 | 很少指定，用函式庫預設的平滑曲線；指定時多半是等速或「去了再回來」 | 一律平滑；計數、模擬用等速 |
| 顏色 | 黃 1260 次、白 976、藍 800、紅 704、青綠 547、粉紅 358、綠 337 | 色票和各色的用途 |
| 字級（橫式） | 36、72、60、30、24、90、48 | 標題 72、內文 48、標籤 30–36；直式減半 |
| 線寬 | 2、1、3 最常見 | 線條的規則 |
| 全域設定 | 3840×2160、30 格、底色 `#000000`、飽和度 1.5、CMU Serif | 畫面的規則 |
| 場景結構 | 一支影片 45–190 個小場景；補充場景 476 個裡 365 個結尾是停住 | 一個場景一個想法；結尾停住、場景之間硬切 |
| 逐年變化 | 2025–2026 的場景：畫面上的字更少、不再出現吉祥物、動作更長、用細框和調暗取代填滿的黃色方塊 | 以近兩年的做法為準 |
